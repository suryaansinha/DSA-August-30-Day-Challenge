# Intuition

An array that was originally sorted in non-decreasing order and then rotated will have at most one "break point" — a place where an element is greater than the element right after it. This happens exactly at the point where the rotation wraps around. If there's more than one such break, the array can't be a rotated version of a sorted array. We also need to check the wrap-around pair (last element vs. first element), since the rotation could bring the largest element right before the smallest.

# Approach

1. Initialize a `count` to track the number of "breaks" (places where a larger element is immediately followed by a smaller one).
2. Loop through the array from index `1` to `n-1`, comparing each element with its previous one (`nums[i-1] > nums[i]`). Increment `count` whenever this condition holds.
3. After the loop, separately check the wrap-around case: compare the last element with the first (`nums[n-1] > nums[0]`). Increment `count` if true, since this represents the break caused by rotation.
4. If `count` is `0` or `1`, the array is sorted and possibly rotated — return `true`. If `count` is `2` or more, it can't be represented as a rotated sorted array — return `false`.

# Complexity

- **Time complexity:**
$$O(n)$$
The array is traversed once to count the breaks.

- **Space complexity:**
$$O(1)$$
Only a constant amount of extra space (`count`, `n`) is used.

# Code
```cpp
class Solution {
public:
    bool check(vector<int>& nums) {
        int count = 0;
        int n = nums.size();
        for(int i = 1; i < n; i++){
            if(nums[i-1] > nums[i]){
                count++;
            }
        }
        if(nums[n-1] > nums[0]){
            count++;
        }
        return count <= 1;
    }
};
```
